## 结论速览

**改动 A（开孔）判定：不通过——开孔从未生效。** `occluder_cutout.gdshader` 用 `##` 作注释，而 Godot 4.7.2 着色语言只认 `//` 与 `/* */`，着色器在首次遮挡同步时即编译失败（engine.log:13/25，backtrace `town_presenter.gd:342 _apply_occluder_cutout`）。编译失败后材质静默回退为普通不透明绘制，同时 presenter 将遮挡件 alpha 恒置 1.0（`piece.modulate.a = 1.0`，旧整件淡出路径已移除），结果是：**凡被覆盖的人物（hero 与居民）都被遮挡件完全吞没，无孔、无淡出、不可读**——比 R4B 的"分档淡出"明显倒退。改动 B（碰撞放宽）数值全部精确生效，判定通过。

## 根因与修复建议（未改动任何代码/素材）

`src/presentation/occlusion/occluder_cutout.gdshader:3-6` 使用 `##` 注释。Godot 着色语言无 `#` 注释，分词器直接报错：

```
SHADER ERROR: Tokenizer: Unknown character #35: '#'   (occluder_cutout.gdshader:3)
ERROR: Shader compilation failed.                     (经 _apply_occluder_cutout → set_code)
```

该错误在 00:29 的中断尝试与本轮会话中均复现（同一文件 mtime 00:22 未变过）。编译失败后 GLES3 兼容渲染器将材质静默回退为普通绘制，叠加 `town_presenter.gd` 中 `piece.modulate.a = 1.0`（整件淡出已移除），形成"全覆盖无开窗且不可读"。修复只需把 4 行 `##` 改为 `//`（或删除）；修复后本轮全部覆盖位、开关孔时序（`inner_alpha = lerp(1, 0.18, 1−eased)` 的缓动已就位）与多 actor 孔位（`occluder_holes` 聚合已就位）需按本轮同路线复验。

## 汇总

改动 B（碰撞放宽：灯柱 5.5、树干/训练桩 8.5）**数值与体感通过**：三类碰撞体停距与理论值差 ≤1.3px（多为 0），楔口滑行、木堆/围栏/契台无穿透、无新增卡死点，R4B 钉点全部复现。改动 A（遮挡开孔）**不通过**：着色器 `##` 注释导致编译失败，开孔特性整体未生效，被覆盖人物（含布告板 NPC iven、tree_east 的 mira）全部不可读，较 R4B 的分档淡出倒退；回归项除"布告板 NPC 可见"外全部维持。本轮未改动任何代码与素材，工作区仅新增本报告与会话证据。
